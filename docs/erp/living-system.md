# ERP 工作台的连接与返回环

这是独立 ERP 分支的核心业务扩展，故随核心 baseline 安装，而不是可卸载的 CRM optional module。用户明确要求 ERP 主导，原 CRM 模块作为客户经营辅助。

| 检查点 | 实际落点 |
|---|---|
| 输入 | 登录组织、仓库权限，销售单、采购单、库存流水；`fn_erp_snapshot` 为账本读取入口 |
| 输出 | `/app/erp` 的业务操作与分析；`fn_erp_command` 原子记账 |
| 日志 | 业务事务内 `erp_audit`，API `erp.command` 写入平台审计 |
| 可见性 | 工作台单据状态、余额、流水、核销与审计；Agent 区显示分析与评测 |
| 入口 | `lib/navigation/catalogo.ts` 注册入口，`/app` 导向 `/app/erp` |
| 下一步 | 草稿→提交→审批→下单→分批收货；销售单→预占→发货；明确取消或退货 |
| 配置 | 工作台基础资料/权限/公司审批策略；组织 AI 设置与可选 Jev 环境配置 |
| 人机连续性 | 分析输出可核对的缺口、版本证据和建议；人工提交采购与审批；下一轮读取当前账本 |
| 失败返回 | 库存或单据变化时拒绝旧版本；评测不确定时交人复核；可确认或撤回 Memory 后影响后续分析 |
| 架构 | `docs/architecture/erp.md` 描述 UI→鉴权→RPC→账本→Agent→人工操作的闭环 |

界面展示实时重新读取的快照，不承诺自动刷新期间没有变化。每次提交仍在数据库事务内复验。没有配置通知或定时催办，因此待审批等下一步依赖操作者进入工作台查看；不能声称已有自动催办闭环。
