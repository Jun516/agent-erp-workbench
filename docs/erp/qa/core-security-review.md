# ERP 核心独立审阅与数据库回归

2026-11-09，基于本分支0409/0410源码和独立 PostgreSQL 15.19 测试库。

## 已修复

1. 补货草稿须携带模型当时看到的销售单与库存版本；SKU须属于关联销售单，数量扣除已关联采购的待收余量，草稿也计入，防止重复补货。
2. 提交/审批/下单复验库存及源销售单版本；采购下单再次核对审批人当前角色、公司额度与职责分离策略。
3. 幂等重放也核对当前角色与仓库能力。成员身份仍有效但收货授权已撤回时，旧收货收据也不能重放；管理员降级后不能重放基础资料/盘点等特权操作。
4. Agent历史分析读取已由Agent实现者补充当前事实/策略版本校验，旧Jev结果不能使失效分析继续显示可采纳。Jev共享文案说明可见报告可能包含Memory派生内容。

## 已核对的边界

- 模型工具仅有读取程序证据、读取已确认Memory和提交分析三个入口，没有采购/审批/收货/付款工具。采购草稿经统一业务命令，在数据库事务内核对来源版本和业务数量。
- 0409所有核心表开启RLS并显式撤销默认ACL；直接REST写表无法绕过库存流水。
- 0409仅快照和业务命令RPC向service_role开放；内部库存/授权/补货primitive不对匿名或登录角色暴露。
- 0410三张持久表server-only，service_role仅有SELECT/INSERT/UPDATE，没有DELETE/TRUNCATE/TRIGGER/REFERENCES。Memory范围的多态引用由服务端在当前快照内验证，不是由客户端名称推断。
- 0410没有新增函数；baseline中0409与0410均位于末尾anon函数扫描前，并各自显式收紧表权限。末尾函数扫描不会替代对表权限的撤销。

## 实测

`scripts/erp-db-regression.mjs`通过56项真实数据库检查，逐项记录在`database-results.json`。包括并发预占防超卖、并发幂等、流水余额恒等、跨租户/跨公司阻断、分批收货、退货、调拨、应收应付核销、撤权、过期证据、过量补货、默认ACL和幂等迁移。

负控制：在一个最终回滚的事务中临时关闭补货数量规则，确认拒绝重复补货的断言确实失败；该控制不留数据库修改。

`tests/invariants/erp-ledger.test.ts`将同一脚本接入仓库canonical隔离数据库测试入口。核心契约与测试文件ESLint检查通过。此报告不表示模型/Jev线上准确率、第三方ERP/支付集成、正式生产容量或PG17矩阵验证。
