# ERP 工作台使用与交互约定

本 fork 的登录后首页跳到 `/app/erp`，侧栏首组为 ERP 经营，公开首页 `/` 也提供入口。CRM 客户管理仍通过 `/app/contacts` 使用。页面品牌沿用安装品牌解析器，不固定为上游 CRM 名称。

## 第一次使用

1. 在“基础资料与权限”创建公司，并在页面顶部选定经营主体。登记该公司的仓库、供应商和商品 SKU。
2. 经理或管理员设置采购审批金额上限，并授权组织成员的仓库采购、收货和发货能力。默认采购申请人与审批人分离。单人本地演练可以显式启用允许同人审批。
3. 选择当前仓库，在“库存作业”登记期初盘点库存。日常差异走库存调整，跨仓移动走调拨，并填写真实依据。
4. 在“销售与采购”新建销售订单，可添加多条 SKU、数量和当前币种单价。
5. 在“Agent 分析与记忆”选择销售单，运行规则分析或已配置的组织模型。先核对可用库存、未覆盖缺口、已有采购计划、交期与供应商提示，再确认采购报价，保存草稿。
6. 在“销售与采购”打开采购草稿，提交审批、批准、确认下单。实物到仓后只填本次数量，分批收货；不处理的明细填 0。
7. 打开销售订单，先预占再发货。每次操作自动读取当前单据版本。完成后到“应收应付”登记线下收付款凭证，或按原单办理退货。

## 失败、重试与证据

- 普通操作使用当前公司和仓库，服务端同时复核组织、仓库权限、状态和金额。基础资料、期初盘点、盘点调整和财务核销需要经理或管理员；Jev 复核和 Memory 确认、撤回也需要该权限。
- 页面保留失败操作的业务幂等键。“核对并重试上次操作”重复发送相同内容，已入账操作返回原收据，不重复改变库存。版本冲突时应刷新、重新核对，再提交新的业务请求。
- 从 Agent 建立采购草稿使用分析时的销售单版本和库存版本，不能偷偷换成刷新后的版本。草稿成功后本次建议的生成按钮停用，需要继续补货时重新分析。
- `model` 运行失败会清楚显示失败状态；规则参考计算仍可见，不能标成模型成功。Jev 当前固定阈值 0.8 尚未经过真实业务标注集校准，评测结论不能代替采购审批。
- Jev 发送材料前要逐次勾选明确分享；未配置服务或未确认时不能提交。Memory 保存前需人工确认、指定业务对象和有效期，并支持撤回。即时库存始终读取账本。

## 代码和验证

- `app/app/erp/page.tsx`：经过真实认证的页面入口。
- `app/app/erp/_components/ErpWorkbench.tsx`：公司、单据、库存、账款和审计页面；首次请求可取消，事件回调中加同步锁防止双提交。
- `app/app/erp/_components/AgentPanel.tsx`：分析历史、证据表、采购建议、Jev 分享确认与 Memory 管理。
- `lib/navigation/catalogo.ts`：统一导航入口。
- `tests/unit/erp-workbench.test.tsx`：幂等重试、只读禁写、分批收货版本、单据下一步。
- `tests/unit/erp-agent-panel.test.tsx`：Jev 分享门槛、原始分析版本绑定、草稿成功后停用、经理权限。

交互单测使用受控 API 响应，验证前端状态和请求协议；不代替真实数据库与浏览器端到端验收。真实业务回归和截图由主任务的 QA 记录提供。
